### Правила против повторной работы

1. Перед началом читать этот реестр и открывать только файлы активной задачи.
2. Если участок имеет состояние **статически локализовано** или **статический аудит пройден**, не запускать его общий аудит заново. Вернуться к нему можно только при конкретной регрессии, новом изменении файла или найденном вызове, который не был охвачен.
3. Для каждого нового участка сначала зафиксировать ID, точные файлы и критерий закрытия; затем выполнять изменения.
4. Разделять три факта: **строки переведены**, **статический путь проверен**, **сценарий реально запущен**. Один не подменяет другой.
5. Записывать коммит и результат проверки после завершения логического участка, а не после каждого мелкого изменения. Не считать количество коммитов мерой прогресса.
6. Если исследование не выявило нового пробела, фиксировать «проверено, изменений не требуется» и больше не возвращать участок в очередь без причины.
7. Не запускать повторный широкий поиск по уже закрытым каталогам ради статуса. Следующий шаг всегда берётся из последней строки активной очереди.
