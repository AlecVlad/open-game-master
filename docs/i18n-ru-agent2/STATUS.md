### Текущая задача: B2-SETUP-READOUT

В область задачи входят только следующие связанные пути:

- `src/lib/workshop/fight-setup-logic.ts` — `describeFightSetup()`, `hurtWords()`, `heroWords()` и составление строк состояния.
- `src/app/api/campaigns/[campaignId]/dm/encounter-templates/route.ts` — выдача описания в списке столкновений.
- `src/app/api/campaigns/[campaignId]/dm/encounter-templates/[templateId]/setup/route.ts` — выдача сохранённой расстановки и её описания.
- `src/app/workshop/encounters/EncounterRows.tsx` — отображение строк описания в Workshop.
- `src/lib/workshop/test-fight.ts` — системная заметка при открытии теста из сохранённой расстановки.
- `src/lib/workshop/fight-setup.ts` — заметка о другой группе персонажей.
- `src/lib/dice-script-logic.ts` — описание костей, используемое в составе readout; проверить, какие строки действительно попадают в пользовательский интерфейс.

**Критерий закрытия задачи:** описания и заметки отображаются на выбранном языке; имена персонажей, противников, названия условий и авторский контент остаются данными; системная заметка не раскрывает служебные маркеры в истории или контексте ИИ; старые API-поля и сохранённые записи не ломаются; EN/RU-ключи и параметры сверены; связанные тесты дополнены. Сам факт изменения словарей не считается закрытием.

### Правила против повторной работы

1. Перед началом читать этот реестр и открывать только файлы активной задачи.
2. Если участок имеет состояние **статически локализовано** или **статический аудит пройден**, не запускать его общий аудит заново. Вернуться к нему можно только при конкретной регрессии, новом изменении файла или найденном вызове, который не был охвачен.
3. Для каждого нового участка сначала зафиксировать ID, точные файлы и критерий закрытия; затем выполнять изменения.
4. Разделять три факта: **строки переведены**, **статический путь проверен**, **сценарий реально запущен**. Один не подменяет другой.
5. Записывать коммит и результат проверки после завершения логического участка, а не после каждого мелкого изменения. Не считать количество коммитов мерой прогресса.
6. Если исследование не выявило нового пробела, фиксировать «проверено, изменений не требуется» и больше не возвращать участок в очередь без причины.
7. Не запускать повторный широкий поиск по уже закрытым каталогам ради статуса. Следующий шаг всегда берётся из последней строки активной очереди.
