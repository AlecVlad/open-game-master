# Interface language (English / Russian)

The interface can be shown in English or Russian. The choice is a cookie
(`ogm-lang`), set in Settings > Appearance; with none, the browser's
`Accept-Language` decides; with neither, English. The language the *story* is
told in is a separate, per-campaign setting (`TableLanguage`).

## How it works

- `src/lib/i18n/core.ts`: pure functions (language choice, `{param}`
  substitution, plural forms, English fallback). Tested by
  `node scripts/test-i18n.mjs`.
- `src/lib/i18n/messages/en/*.ts`: the source of truth, one file per area,
  keys shaped `area.screen.thing`.
- `src/lib/i18n/messages/ru/*.ts`: the same keys, `Partial`, so a message a
  language lacks is shown in English. Register a new area in
  `messages/index.ts`.
- Client: `useT()` from `src/lib/i18n/provider.tsx`. Server components:
  `getT()` from `src/lib/i18n/server.ts`.
- Counts: keep one entry per form (`.one`, `.few`, `.many`, `.other`) and call
  `tp(key, count)`.

## Not translated

Identifiers, env variable names, API routes, DM tool names, prompts and any
error text meant for the model, SRD content (spells, monsters, rules text).

The current localization state, active work queue and local-machine checks are

and [docs/i18n-ru-agent2/PLAN.md](./i18n-ru-agent2/PLAN.md).

The working branch is based on the stable upstream release `v0.35.1`
(commit `044b9dcd0409c5b862a77241de6f18311f497f74`). The merge is recorded in
`i18n-ru-agent2`; the app package version is `0.35.1`.

The merge itself did not run TypeScript, lint, production build, i18n tests or
browser scenarios. Do not treat those checks as passed until they have been
run on the local machine.
